# resources/markers

Checked-in inputs for the annotation stage. Two kinds of file live here.

## `panel_{species}.tsv` — inputs (hand-curated)

The published coarse cell-type marker panels from Cevrim et al. 2025
(bioRxiv 2025.10.08.681007), as drawn in the Figure 1 dotplots. The underlying
markers are canonical endometrial markers drawn from Kirkwood et al. 2021,
Kirkwood et al. 2022, Wang et al. 2020, and Winkler et al. 2024 (the sources
cited in the Methods). Read by `notebooks/curation/04_annotate.ipynb`.

Columns: `celltype`, `role` (`lineage` | `context`), `nested_within`, `genes`
(comma-separated). Row order sets dotplot row order.

Two things these encode that a flat gene list cannot:

- **`role`** separates markers used for *assignment* from markers used only for
  *display*. `PGR`/`ESR1` are expressed across epithelium, fibroblasts, decidual
  cells, SMC and perimetrium; they appear in the published figure for context and
  must never contribute to a cell-type call.
- **`nested_within`** records that decidual cells are a differentiated state of
  endometrial fibroblasts and therefore express the fibroblast markers *as well
  as* their own. Naive argmax over marker-set scores mislabels them, and which
  set wins depends on set size rather than biology. The notebook applies an
  explicit override instead.

The mouse and human panels are **not** translations of each other — the
published human panel uses different markers, and the mouse decidual marker
`Prl8a2` has no human ortholog (rodent-expanded placental prolactin family).

## `annotations_{species}.tsv` — outputs (generated, then hand-adjudicated)

Written by `notebooks/curation/04_annotate.ipynb`, consumed by
`workflow/rules/04_annotate.smk`, which is a pure lookup: map cluster →
celltype, drop `exclude` rows. No judgment happens at pipeline runtime.

Columns: `cluster`, `celltype`, `exclude`, `margin`, `n`, `source_resolution`,
`derived_from`, `adjudication`.

### These files are checkpoint-specific

Leiden cluster IDs are only meaningful relative to one scVI fit. scVI is
stochastic, so re-running `02_integrate` produces a *different* latent space and
cluster `3` becomes a different set of cells — silently. The mapping would still
apply, and would be wrong.

`data/interim/latent_{species}.h5ad` is therefore a **frozen stochastic
checkpoint**, in the same sense as the CellBender-corrected inputs: it ships as
an artifact rather than being regenerated on demand. `source_resolution` and
`derived_from` in each annotations file record which checkpoint and which
resolution the mapping was derived against. If you re-run `02_integrate`, these
files must be regenerated by re-running the notebook.
